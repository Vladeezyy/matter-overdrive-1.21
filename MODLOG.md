# MODLOG — Matter Overdrive 1.21.10 port

## Environment (macOS arm64)
- JDK 21: Homebrew `openjdk@21`, registered in `~/Library/Java/JavaVirtualMachines` → `/usr/libexec/java_home -v 21`.
- Build: `./gradlew build` → `build/libs/matteroverdrive-<ver>.jar`. Dev game: `./gradlew runClient`, log `run/logs/latest.log`.
- References: `~/mo-reference/mo-1.7.10` (spec), `~/mo-reference/mo-ce-1.19.2` (modern patterns). Original jar: `_original/` (gitignored).
- Dev client uses its own `run/` folder, so the user's real Minecraft worlds are never touched.

## 2026-10-08 — slice 1: mod loads with base content ✅
- Scaffolded from NeoForgeMDKs/MDK-1.21.10-ModDevGradle (NeoForge 21.10.64).
- Registered 3 blocks (tritanium_ore, dilithium_ore, tritanium_block; hardness from 1.7.10) and 16 plain items.
- Resources generated by a script from the 1.7.10 assets: item models + 1.21.4+ `assets/<mod>/items/*.json`
  client item definitions, blockstates, loot tables, mineable/needs_iron_tool tags, lang en_us + ru_ru
  (converted from `.lang`: `item.X.name` → `item.matteroverdrive.X`, `tile.X.name` → `block.matteroverdrive.X`).
- Verified: `./gradlew build` OK; `runClient` loads to title, no matteroverdrive warnings/errors in latest.log.

### Gotchas
1. 1.21.4+ needs a client item definition in `assets/<mod>/items/<id>.json` in addition to `models/item/` — without it items render as missing.
2. Some ru_RU strings are missing in the original (weapon_handle, weapon_receiver, plasma_core); translated in `EXTRA` in tools/gen_resources.py.

## 2026-10-08 — phase 1: base content ✅
- Resources now come from `tools/gen_resources.py` (in repo): regenerate with
  `rm -rf src/main/resources/{assets,data} && python3 -I tools/gen_resources.py ~/mo-reference/mo-1.7.10/src/main/resources/assets/mo src/main/resources`.
- Ore worldgen as in 1.7.10 MOWorldGen: tritanium 10 veins/chunk size 6 y 4-63, dilithium 6 veins size 5 y 4-31;
  configured + placed features and `neoforge/biome_modifier` add_features to `#minecraft:is_overworld`. Stone only (no deepslate textures in the original).
- Dilithium ore: `DropExperienceBlock` 2-5 xp, loot like diamond ore (silk touch / fortune), needs diamond tool (1.7.10 harvest level 3).
- Tritanium tools (sword, pickaxe, axe, hoe) — `ToolMaterial(INCORRECT_FOR_IRON_TOOL, 3122, 6, 2, 14)`; armor — `ArmorMaterial(66, 4/9/7/4, ench 20)`.
  Armor worn uses the vanilla-layout `tritanium_layer_*` textures; the original custom 3D armor model (`Tritanium_Armor2_*`, 64x64) is a later render task.
- `isolinear_circuit` damage values 0-3 → items `isolinear_circuit_mk1..mk4`. Only mk1 is craftable now; mk2-4 come from the Inscriber (phase 2).
- 26 recipes from MatterOverdriveRecipes whose inputs already exist (+ block→ingots, blasting). Inputs use `c:` tags.
- `c:` tags for ores, ingots, nuggets, dusts, plates, gems, storage blocks.
- **Oracle**: `./gradlew runGameTestServer` runs `matteroverdrive.gametest.MOGameTests` headless (5 tests: biome modifier attached,
  features place ore in stone, dilithium drops crystal, smelting recipe present, tool tiers). All pass; a deliberately broken assert fails the run.

### Gotchas
3. 1.21.10 GameTests are registry entries: register the function in `Registries.TEST_FUNCTION` and the instance in `RegisterGameTestsEvent`
   (`FunctionGameTestInstance` + `TestData`, structure `minecraft:empty`). The game test world is superflat, so test ore *placement* by calling
   the configured feature on a stone cube instead of scanning generated chunks.
4. macOS has no `timeout`; run long Gradle tasks in the background.
5. Tools in 1.21.5+: sword/pickaxe are plain `Item` with `Item.Properties.sword()/pickaxe()`; axe/hoe keep `AxeItem`/`HoeItem` for stripping/tilling.
